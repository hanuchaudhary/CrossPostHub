# Project structure update — completion report

Status: completed

## 1. Split the legacy Next.js application

- Moved the browser UI, stores, hooks, types, styles, fonts, and static assets into `client/`.
- Replaced Next.js App Router pages/layouts with React Router routes and protected layouts.
- Added small React compatibility components for the legacy `Link`, `Image`, and navigation call sites.
- Removed browser-side Prisma/database packages and all Next.js runtime imports.
- Added a Vite development proxy for `/api` and `/media`.

## 2. Move server behavior to Hono on Cloudflare Workers

- Reimplemented the legacy API surface as Hono routes in `api/src/routes.ts`.
- Added authenticated user, connected-app, notification, pricing, subscription, transaction, post, media, dashboard, GitHub profile, caption-generation, and image-generation routes.
- Added CORS handling for the separately hosted React client.
- Added a typed Cloudflare Worker entry point and environment bindings.
- Migrated and normalized the Prisma data model for Better Auth and Dodo Payments.
- Added a Dodo-aware pricing-plan seed script.

## 3. Replace NextAuth/Auth.js with Better Auth

- Added Better Auth email/password, Google, LinkedIn, and Twitter configuration.
- Mounted Better Auth at `/api/auth/*` in the Hono worker.
- Added Better Auth's Prisma adapter and the required `User`, `Session`, `Account`, and `Verification` schema.
- Replaced all client `next-auth` usage with the Better Auth React client.
- Replaced the old custom Twitter OAuth route with Better Auth social account linking.

## 4. Replace Razorpay with Dodo Payments

- Removed Razorpay code, identifiers, checkout script, and package references.
- Added the official Dodo Payments SDK and Better Auth plugin.
- Added Dodo customer synchronization on signup, hosted checkout, customer portal, and verified webhook support.
- Checkout sessions are created server-side and redirects are used only for navigation.
- Subscription and payment access is synchronized from verified webhook payloads.
- Added idempotent payment/subscription upserts and Dodo product/customer/subscription fields to Prisma.
- Dodo defaults to `test_mode`; live mode must be selected explicitly.

## 5. Replace QStash with Cloudflare Queues

- Post creation now writes a database record and sends a typed Queue message.
- Queue consumers publish posts, update post status, and create success/failure notifications.
- Failed work retries with backoff and is marked failed after the retry limit.
- Scheduling beyond Cloudflare Queue's per-message delay window is handled by re-enqueueing until the requested publish time.

## 6. Replace S3 with Cloudflare R2

- Added the `MEDIA_BUCKET` R2 binding.
- Added authenticated direct-upload and owner-checked delete endpoints.
- Added public object delivery through `/media/*` with object metadata and immutable cache headers.
- Queue consumers read media directly from R2 for LinkedIn publishing.

## 7. Configuration and deployment

- Added `api/.dev.vars.example` for server secrets and provider IDs.
- Added `client/.env.example` for the API URL.
- Added Cloudflare Queue and R2 configuration to `api/wrangler.jsonc`.
- Added database generation, migration, and seed scripts.

External setup still required before deployment:

1. Create the `posthub` Cloudflare Queue and the `crossposthub-media` R2 buckets, or rename the bindings in `wrangler.jsonc`.
2. Add Worker secrets from `api/.dev.vars.example` with `wrangler secret put`.
3. Create the Dodo products, set their IDs, seed the plans, and register `https://<api-domain>/api/auth/dodopayments/webhooks` in the Dodo dashboard.
4. Apply a Prisma migration to the target PostgreSQL database.
5. Configure the Google, LinkedIn, and Twitter OAuth callback URLs for the API domain.
